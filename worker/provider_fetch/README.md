# Private provider fetch runtime

`subs-bot-provider-fetch-dev-01` is a separate Worker with a single Container instance managed by a Durable Object. Its default Worker handler returns a fixed 404. The configuration disables workers.dev, previews, invocation logging and traces. The Container uses a nonroot Python process with no project credentials, data bindings or storage mounts. Direct Internet access allows public DNS and numeric dialing. The application checks every destination before it connects.

The private port exposes `GET /ready` and `POST /v1/fetch`. Fetch accepts only an `application/json` object containing `url`. The response body contains the downloaded bytes, with a SHA-256 header and optional bounded Base64URL metadata. Errors use fixed categories. Only one provider fetch can run at a time. The existing bot and subscription Worker have no binding to this service.

The private `ProviderFetch` named entrypoint exposes `fetchSubscription({ url })` to a future explicit service binding. It uses the same singleton admission and pinned image as the smoke workflow. A successful result contains an `ArrayBuffer` of at most 10 MiB and its verified SHA-256, plus optional validated `content-type`, `content-disposition`, `profile-title` and `subscription-userinfo` metadata. Failures return a fixed category, a retry hint and, for upstream HTTP failures, a validated numeric status. The entrypoint leaves metadata interpretation to its caller. [Named service bindings](https://developers.cloudflare.com/workers/runtime-apis/bindings/service-bindings/rpc/#named-entrypoints)

The hosted Provider Fetch CI job builds the Worker and the Linux amd64 OCI image, verifies the OCI manifest, config and layer digests, and checks that the tested image has the same config digest. It exercises the image without external networking and verifies the emitted Worker returns 404. Before upload, CI uses the publication workflow's pinned Skopeo to copy the exact archive to a local OCI layout and compares its raw manifest and config digests. The copy and inspection run in an isolated network namespace. The hosted artifact contains the exact Worker module, OCI archive and `provider-release.json` with the build ref, revision, run ID and attempt.

Run `gh workflow run worker-provider-artifact-preflight.yml --ref main -f provider_ci_run_id=<run-id>` against the successful Provider Fetch CI build of current `main`. The preflight checks the run, streams and verifies GitHub's archive, and verifies all three files in private runner storage. It uses only read access to GitHub. Earlier manifest versions are ineligible. For a later release, `release_artifact.py config` also requires the verified source run ID and attempt with `--run-id` and `--run-attempt`, and an explicitly supplied account ID.

Activation selects the sole pinned Worker version at 100%. It verifies the exact deployment ID and private settings, then resolves the sole SQLite namespace for `ProviderContainer`. Container creation binds the fixed name to that namespace, which is also its application ID, with application logging and SSH disabled. A complete bounded application inventory establishes both name and namespace absence without assuming an undocumented Containers 404 code. The inventory admits at most 500 applications on one terminal page and a 64 KiB response. Namespace inventory admits at most 1000 rows on one terminal page. Oversized, incomplete or ambiguous inventories stop the operation. The private Workflow `subs-bot-provider-fetch-dev-01-smoke` is triggered through Cloudflare’s authenticated Workflow API. Use instance ID `provider-smoke-<provider revision>` and parameters `providerRevision` and `isolatedRevision`. Verify the deployed Worker and image first. The smoke accepts one attempt per provider revision, starts one `lite` instance, and tests the existing isolated subscription Worker’s fixed `/health` using only validated Cloudflare edge addresses and no redirects. It also checks rejection of IPv4 loopback, IPv6 loopback and a link-local address, then destroys the instance. Require `ok: true` and an independent stopped-state readback. DNS family counts show which answers were approved. A separate test is required to establish IPv6 connectivity. [Workflow instance API](https://developers.cloudflare.com/api/resources/workflows/subresources/instances/) · [Container lifecycle](https://developers.cloudflare.com/containers/api/durable-object-container/)

The protected smoke requires no previous actors, Container instances or Workflow instances. It sends the exact two parameters once, polls the deterministic instance, and compares its bounded serialized output with the independent health bytes, revision and OCI digest. Verification requires one stored Durable Object actor and its exact Container instance in fresh `stopped` state, plus a complete empty active-instance listing. Pass `isolated_revision` again when verifying an existing smoke. A failure or interrupted run is reconciled through reads and retains its one-shot receipt. Public denial checks use the fixed provider workers.dev URL together with independently disabled workers.dev/previews and logging metadata. The runtime's fixed 404 alone does not establish edge privacy. ### Provider binding proof

The protected activation workflow publishes `subs-bot-provider-binding-proof-<provider-revision>-<run-attempt>` only after `smoke` completes or read-only `verify` confirms the same completed smoke. The final checks include public denial, independent Container shutdown, and exact provider resource and `main` readback. The artifact contains one canonical version 1 `provider-binding-proof.json`. It records the verified Provider Fetch CI artifact and module/OCI digests, the activation run and attempt, isolated health revision and digest, and fingerprints for the observed account, Worker, version, activation, Container, Workflow and actor. The artifact expires after 30 days. A verification dispatch with the same provider revision still current on `main` can produce fresh evidence without another smoke mutation.

A future binding workflow must select the exact successful `workflow_dispatch` run of `worker-provider-isolation-activate.yml` from this repository's `main`, match the workflow identity, commit and attempt, and verify GitHub's artifact archive SHA-256. Require one bounded regular manifest in the archive and validate it against the authenticated run metadata. Compare the proof with protected identity pins and fresh Cloudflare readback of the provider account, immutable Worker, private settings, active deployment, version, module, OCI digest and Durable Object namespace before activating a caller. The proof covers the fixed isolated health smoke and records the private provider state at verification time. This workflow publishes evidence only.
